### Verified local engineering runtime

The test-only Dockerfile/entrypoint live in `scripts/ocr-runtime/`; the pure selective contract and container adapter are in `app/lib/server/ocr/`. Production Dockerfiles, legacy worker calls, storage/RPC schemas and feature flags are unchanged. The caller must authorize source/owner context and supply an immutable image ID built from this reviewed source; arbitrary image IDs do not attest the static engine metadata. Cleanup has a bounded grace period beyond recognition cancellation; production orchestration must explicitly budget that before integration.

## Context

AA011 provides immutable native-PDF geometry and reading-order hypotheses. AA012 needs a real adapter for scanned/mixed PDFs with selective processing, geometry, confidence, provider metadata, bounded retries, cost accounting, and safe failure. Current code detects pages with fewer than eight non-whitespace native characters; that is a routing heuristic, not proof of scan quality or a release accuracy gate. The current OCR adapter accepts whole-document bytes, returns whole-document text and one confidence value, and defaults to disabled/unapproved with zero spend. It cannot yet implement selective page provenance or the proposed output contract.

Provider confidence is not calibrated accuracy. OCR must not silently replace usable native text or turn uncertain fields into scoring facts. AA013 owns reconciliation/confidence calibration; AA015 owns representative release-corpus evaluation. No provider has been benchmarked in this proposal.

## Decision proposed

Use native extraction first. Evaluate **self-hosted Tesseract 5 in the existing worker infrastructure** as the initial adapter, subject to verified native-binary support, renderer isolation and approved processing location. The owner does not use Google Cloud; do not require or provision a new cloud account. Supabase remains the private upload/evidence store, not the OCR engine. Pin the engine, language data and renderer versions. This recommendation follows the existing-infrastructure constraint, not a measured accuracy ranking. [Tesseract engine and licensing](https://tesseract-ocr.github.io/tessdoc/).

Use no automatic vendor fallback. If local recognition is unavailable or inadequate, preserve native evidence and return an explicit OCR-required/review/unsupported state. Managed alternatives below remain comparison references only, requiring separate approval and account/region/privacy validation. Do not implement four adapters or route data to external OCR by default.

## Evaluation policy (AA0 design accepted; execution prerequisites remain)

- **Input:** synthetic English printed-resume PDFs only for initial adapter verification; no real candidate data, handwriting, model training, paid add-ons, or public demo uploads. This is an engineering test scope, not approval of the first release domain/locale.
- **Disclosure:** self-hosted-only for the initial evaluation; no external OCR requests. Run recognition only on selected rendered pages and preserve usable native text. Existing private Supabase access continues under the owner/purpose policy. Verify the worker's actual host and location; do not infer its residency from the Supabase region. Any later external OCR requires separate approval.
- **Retention:** transient local memory or owned isolated scratch files only; delete rasters and scratch text on success, rejection, timeout and cancellation. No OCR content in operational logs, no persistent staging buckets and no training. Original uploads/evidence retain existing export/deletion controls. Verify host logs, crash dumps and backups; self-hosting does not make retention controls automatic.
- **Budget:** proposed maximum **$5 USD total** for synthetic evaluation and **$0.05 estimated incremental compute/rendering cost per document**, including retry work. External OCR spend is **$0** because it is prohibited. Engine API fees are zero, but compute costs remain estimated/unknown until a host rate is supplied; do not call the pipeline free. Reserve conservative compute costs before work; if cost cannot be bounded, require an explicit bounded local-only allocation. These are proposed ceilings, not incurred charges. A managed comparator would require separate per-attempt/billing approval.
- **Bounds:** at most ten OCR pages per document, sequential bounded rendering at up to 300 DPI, ten megapixels per page and 100 megapixels total; existing byte/page/text limits still apply, with the stricter cap winning. Proposed end-to-end OCR deadline 30 seconds, per-attempt cap 10 seconds, concurrency two, and at most one retry within the remaining time and cost reservation. These targets must be checked against current worker deadlines before implementation.
- **Retries:** retry only documented transient errors with capped jitter/backoff. Never retry invalid input, policy/region failures or authentication errors. Persist per-attempt accounting and idempotency; reconcile ambiguous charged timeouts before any resubmission. There is no silent fallback or unbounded retry loop.
- **Evidence:** raw provider confidence remains `uncalibrated`; missing/low-quality evidence remains explicit. Do not enable authoritative OCR scoring before AA013/AA1 gates. The existing `minimumConfidence` setting cannot establish calibration or be silently applied across providers as a common probability.

## Normalized adapter contract proposed

Freeze under AA002 before implementation. The existing contract will need an additive/versioned upgrade, not an undocumented replacement.

Declare execution mode `self_hosted` versus `external` explicitly. Local OCR must not require falsely setting third-party consent to true. Apply provider-disclosure consent only to external adapters, while preserving purpose/owner authorization for both. Separate zero local API fees from bounded compute estimates; the current preflight rejects a zero cost limit and therefore needs an explicit local-cost contract, not a policy bypass. For self-hosted execution, timeouts/cancellation must terminate the isolated recognition/rendering processes and clean scratch resources, not merely abandon a JavaScript promise. The current Node 22 Alpine runtime image has no Tesseract/renderer installation step; dependency/image changes and deployment-host support remain unverified.

1. Request includes immutable document checksum, analysis/tenant identity, selected original page IDs, rendered image checksums/dimensions, purpose/consent policy, exact region/model version, attempt identity, remaining deadline, and reserved cost ceiling. Provider requests must not contain tenant secrets or unnecessary identity metadata.
2. Response declares `ocr-evidence-v1`, provider/model/API version, region, provider request ID, duration and per-attempt cost status (`estimated`, `confirmed`, or `unknown`). Missing charge information remains unknown and reserves the maximum; it is never coerced to zero.
3. Each OCR page maps explicitly to its **original** page number, even when an image request's provider page is always page 1. Preserve OCR text separately from native text; use Unicode code-point offsets with validated word/line spans, normalized top-left polygons, renderer transforms, units and rotation provenance. Reject missing/duplicate/extra page identities, malformed geometry and ungrounded spans.
4. Preserve raw provider scores and score scale, plus normalized scores only where a documented conversion exists. Tag confidence `uncalibrated`; do not average away low-confidence critical words or invent absent confidence/boxes. Keep provider ordering distinct from any derived reading-order hypothesis.
5. Failures identify policy rejection, unsupported input, malformed output, timeout/cancellation, transient outage, cost exhaustion and low-quality/review states. No failure returns fabricated successful text. Emit bounded metadata-only audit events, never resume text, polygons containing text, API keys or signed URLs.

## Bake-off protocol and exit boundary

1. Before execution, approve this policy; freeze AA002 contract details and AA003 synthetic governance. Verify the worker host, region, process/memory/time limits, engine/language/renderer versions, isolation, scratch lifecycle and compute rate. Do not install dependencies, change runtime images or create infrastructure during proposal preparation. Keep OCR disabled outside the explicit test runtime.
2. Create a checksum-pinned synthetic manifest with **24 documents**: six clean image-only scans, six challenging scans (150 DPI, skew, blur/compression), six mixed documents (including a native page between scanned pages), and six controls/adversarial cases (native-only, genuinely blank page, rotated input, malformed/encrypted input, oversized image, duplicate/missing provider pages). Keep scan/layout variants declared rather than averaging them away. The test content includes fabricated names/emails/phones, employers, roles, dates, education and skills with independent expected text/word/page labels.
3. Split underlying source documents, not their rendered variants, into development and locked evaluation sets. Record partition/provenance and require two annotations plus adjudication for evaluation labels. Synthetic labels can verify the adapter but do not replace representative consented real-data governance or release-domain evaluation.
4. Run native-only controls with zero OCR invocations. Compare expected labels, native control extraction and actual self-hosted recognition on pinned scanned/mixed images. Include a managed comparator only after separate approval, using identical images/settings. Record all attempted pages, omissions, failures, estimated costs and cleanup. Do not drop failed fixtures or fabricate benchmark values.
5. Report character error rate `(substitutions + deletions + insertions) / reference characters`, original-page coverage, critical-field precision/recall, exact-position ordered-line agreement, geometry grounding, success/abstention/error rates, cold/warm end-to-end latency p50/p95 and maximum, attempts, total cost and cost per selected page. Include per-segment counts and bootstrap intervals grouped by source document with a fixed seed; small synthetic intervals do not establish representative release confidence.
6. Apply the unchanged proposed `CONSTRAINTS.md` release floors as screening targets: clean-scan CER at most 1%, challenging CER at most 3%, critical-field precision at least 98%/recall at least 97%, reading-order agreement at least 98% single-column/95% supported multi-column. They remain proposed segment-specific release gates, not claims established by this paper comparison. Adapter tests require full original-page accounting, zero native-page OCR calls, zero fabricated fields, no unauthorized call/spend and safe failure.
7. Inject timeout, cancellation, 429/5xx, invalid credentials, unavailable region, malformed/nonfinite geometry/confidence, empty output, missing/extra pages, actual cost overrun and charged/ambiguous retry outcomes. Verify retry and aggregate reservations, native-page immutability, review states, redacted logs, scratch deletion and owner isolation. A recorded/replay response verifies normalization only; at least one real synthetic scanned and mixed request must verify the selected live adapter before AA012 completion.
8. Publish a measured report and select **one** adapter only after quality and privacy gates pass. If no candidate passes, do not relax targets or force a numeric score: revise scope/provider or keep OCR unsupported. AA012 completion covers its adapter acceptance; AA013 reconciliation, AA015 representative calibration, AA1 and production Gate A4 remain separate. Exit allows changing the adapter without changing canonical evidence, native checksums, or ownership.

## Consequences

This minimizes unnecessary external processing and keeps vendor choice reversible, but adds rasterization/isolation, page remapping, contract validation, attempt accounting and failure handling. Local OCR has operational costs; managed OCR adds subprocessor/consent obligations. A successful API call is insufficient evidence of AA012 completion. Approval of evaluation is not approval to disclose real resumes or deploy production OCR.
