## AA000 — capabilities and truthful claims

| Capability            | Approved-direction target                                         | Present evidence boundary                                                                                     |
| --------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Document evidence     | Native extraction, selective local OCR, provenance and review     | Native evidence/layout implementation and synthetic fixtures only; no OCR or representative-corpus validation |
| Canonical content     | Structured facts, candidate confirmation, immutable revisions     | Design, not implemented authoring acceptance                                                                  |
| Job intelligence      | Source-cited requirements with required/preferred distinctions    | Existing matching is not validated v2 requirement extraction                                                  |
| Scoring               | Separate deterministic compatibility/alignment, gated by evidence | Legacy results and regression tests are not v2 calibration                                                    |
| Authoring             | Grounded drafts, accept/reject/undo, source-visible changes       | Target, not accepted end-to-end workflow                                                                      |
| Rendering             | PDF/DOCX parse-back; LaTeX separately gated later                 | Target; no verified-export claim                                                                              |
| Recruiter calibration | Separate later human-approved mode                                | DEFERRED; no automated employment decisions                                                                   |

Allowed now: “synthetic regression checks passed” or a precisely named native fixture result, with limitations. The five claim levels are (1) regression correctness, (2) held-out corpus validity, (3) validity for a declared domain/locale, (4) controlled named-vendor/version compatibility, (5) separately evaluated application outcomes. Passing one never grants the next. Corpus results must name policy/version, segment, sample, interval, date and exclusions.

Prohibited at every unproven level: universal ATS passage, hidden employer scoring emulation, probability of interview/shortlist/hire, guaranteed improvement in outcomes, autonomous rejection/hiring/application, invented facts, unauthorized scraping, or treating LLM priors as current market evidence. Confidence describes evidence reliability, never candidate merit.

## AA001 — score semantics and worked cases

Decision proposed: show `Evidence Confidence` plus separate `ATS Compatibility` and `Job Alignment`. No aggregate `Application Readiness` score in this scope. Numeric results require an approved, calibrated ruleset; initial weights are research hypotheses, not production defaults. LLM text/classification cannot enter numeric calculation until deterministic validation against the approved requirement/rule contract.

Evidence states are `verified`, `high`, `review_required`, `insufficient`, `unsupported`. Candidate confirmation alone cannot overcome missing pages or failed quality checks. `high` requires calibrated policy, not a provider's raw confidence. Review-required, insufficient, unsupported, failed or incomplete critical evidence withholds affected numeric dimensions, with reason and recovery action. No approved calibration policy means no v2 numeric score.

Each rule has `pass`, `partial`, `fail`, `not_applicable`, or `not_evaluated`; partial credit must be a versioned rubric value. `not_applicable` requires a justified applicability predicate. `not_evaluated` means missing/uncertain evidence, never zero-error success. For eligible rules, score = 100 × sum(weight × credit) / sum(weight). Exclude not-applicable and not-evaluated rules from that fraction; separately report evaluated weight / applicable weight, excluded rules and blockers. Zero denominator produces null, never 0 or 100. A critical unknown or coverage below the approved policy withholds the displayed score even when an internal fraction is calculable.

Illustrative weights below are arithmetic examples ONLY, not the initial ruleset:

| Case                    | Hypothetical rule credits/weights                       | Arithmetic and display                                                                    |
| ----------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Complete evidence       | pass 1/40, partial 0.5/40, fail 0/20                    | 100 × (40 + 20) / 100 = 60; display only if calibrated policy passes                      |
| Unknown third rule      | pass 1/40, partial 0.5/40, not_evaluated /20            | Internal 75 on 80% coverage, not 80 or 100; withhold if critical or insufficient coverage |
| Inapplicable third rule | pass 1/40, partial 0.5/40, justified not_applicable /20 | Internal 75 on 100% applicable coverage; disclose exclusion; policy still required        |
| Nothing evaluable       | all not_evaluated, or all not_applicable                | null with reason, no numeric badge                                                        |
| Failed extraction       | any credits computed from missing critical evidence     | null regardless of fraction                                                               |
| LLM says “95”           | identical verified facts/rules as first case            | No effect: deterministic internal result remains 60                                       |

Compatibility measures observable document recoverability, not hiring quality. Alignment uses only confirmed/verified candidate evidence and cited public-JD requirements; required/preferred findings remain separate. No duplicate-keyword credit; merely listing a skill is not proof of experience. Requirement states: `satisfied`, `partially_satisfied`, `candidate_confirmation_required`, `not_evidenced`, `not_applicable`, `not_evaluated`. Distinguish reliable absence (`not_evidenced`) from uncertain extraction (`not_evaluated`). Mapping these to credit belongs to the approved rubric.

Historical scores remain immutable and labelled legacy, with original scoring version and date. Do not relabel them v2, average them with v2, or plot cross-version changes as improvement. Re-analysis creates a new result; failure does not overwrite history. Candidate-facing explanations show dimensions, coverage, source citations, limitations and version.

## AA002 — versioned contracts to freeze on approval

These are logical contracts for later implementation, not a claim that current database/API JSON conforms. Types below are required unless explicitly nullable; missing, empty and unknown must not be conflated. Strict validators reject malformed references, non-finite values, contradictory states and unsupported major versions.

### Common envelope and invariants

- Each object carries `schemaVersion` (major.minor.patch), opaque `id`, server-derived `ownerId`, `analysisId`, UTC `createdAt`, producing `producerVersion`, and `retentionPolicyId`. Persisted results bind input SHA-256, policy/ruleset versions and immutable source IDs. IDs are stable within an immutable version; different sources/versions cannot share a fabricated identity.
- Authorization is owner-filtered on every read/write/export and source traversal. Never accept client ownership. Private storage only; service privileges do not permit cross-owner joins. Do not include raw text in logs, analytics or error payloads.
- Breaking field/state/coordinate semantics require a new major version; additive optional fields a minor; clarifications a patch. Unknown major versions fail closed. Native v1 evidence/layout retain their names; an adapter must preserve their provenance and cannot invent word polygons or calibrated confidence.
- No implicit correction of source text, ordering, dates or factual claims. Store transformations and their version; preserve original bytes and text. Text ranges use Unicode code-point offsets, half-open `[start,end)`; coordinate boxes use top-left normalized page coordinates `[0,1]`, with units, dimensions, rotation and geometry quality explicit.
- Every read model returns explicit availability/review/failure states. Unknown values are null with reason, not empty arrays suggesting success. Bounds inherit existing upload/page/text/deadline limits; a later implementation cannot enlarge them without review.

All state transitions are server-validated and compare the expected immutable base version. Stale edits return conflict and require re-review. Idempotency keys bind owner, operation and input hash; a key reused with other inputs conflicts. Cancellation/deletion invalidates derived jobs and prevents a late worker publishing results. Retryable failures are explicitly classified, bounded and recorded; terminal/unsupported inputs do not spin. Public errors contain safe codes/recovery actions, not provider payloads or document text.

Deletion follows the privacy map: revoke access first, database deletion/cascade, private-object cleanup with retry and auditable non-PII receipts. All derived versions, evidence, suggestions and artifacts inherit deletion and cannot outlive approved purpose/retention. Schema approval does not approve renderer/compiler implementation, production retention changes or migration adoption.

## AA003 — corpus governance and annotation handbook

Initial authorization proposed: synthetic fixtures only, with documented generator/template licenses. No real resume/JD reuse, scraped material or candidate-account data. Separate real-data consent, lawful purpose, de-identification review and privacy approval are required later; corpus permission must not be inferred from upload consent. No raw corpus in public Git history.

Manifest per document: opaque ID, source/license/permission, purpose, source-family/template/near-duplicate group, language/locale/domain, native/scanned/mixed class, layout/scan segment, partition, byte hash, generator version, access group, expiry and deletion status. Synthetic identities must be clearly fictional. Evidence labels include exact text/order, critical fields and spans, typed JD requirements, required/preferred classification, ambiguity and unsupported boundaries; no hiring-outcome labels as sole truth.

Two independent human annotators label critical items without seeing each other's work or model output. Preserve both original labels; a separately assigned adjudicator resolves disagreements with a reason and handbook revision. The author/model cannot impersonate two independent annotators. Names may be appointed before collection; inability to appoint them blocks collection, not a fabricated agreement result.

Pilot annotation: double-label the synthetic set, record categorical agreement (Cohen's kappa when appropriate), precision/recall of spans against adjudicated truth, and exact order agreement. Target agreement ≥0.80; undefined/unstable statistics require more data or rubric revision, not “pass.” Unresolved critical labels are excluded from calibration and explicitly counted. Annotator guidance: absence is not uncertainty; reading order must be inspectable; do not infer employment facts from visual proximity; flag ambiguity instead of guessing.

Split by source family/template/near-duplicate cluster before tuning into development, calibration and locked test; proposed allocation 50/25/25 with disjoint hashes and families. Independent generation families are required, not rotated copies of one template. Release test labels stay hidden from tuning; leakage invalidates the affected gate and requires a fresh lock. The 24-document OCR pilot is feasibility/regression evidence only, never statistically adequate release evidence.

Report every declared segment and all exclusions/failures/abstentions, not just successful parses. Use document-level bootstrap 95% intervals (10,000 resamples, recorded seed); resample whole source clusters where clustered, and document the estimator for macro-F1/correlation. Success-rate lower bounds must meet minima; error-rate upper bounds must meet maxima. Zero observed errors does not establish population-perfect precision: report interval and runtime safeguards, not a guarantee. Sample planning retains the constraints' approximate 203 independent documents/segment starting calculation; clustering/non-binomial metrics need a justified revised calculation before release. No threshold relaxation here.

Proposed local corpus retention: synthetic raw fixtures and labels for 30 days after evaluation, transient OCR scratch only for the attempt and always cleaned on success/failure/cancel; aggregate non-PII reports, hashes, permission/deletion receipts may remain for reproducibility. Future real-data retention needs separate approval. Restricted local access to assigned people, no third-party upload/telemetry or repository inclusion of private material. Revocation removes access and derived labels, invalidates affected evidence/calibration, and triggers deletion verification; report metrics again if their corpus changes. Privacy owner approves these controls; evaluation owner approves handbook, partitions and statistics before collection.

## AA004 — local OCR evaluation, not deployment

Proposed selection for evaluation: native baseline versus local Tesseract 5, exact engine/renderer/language-pack versions pinned when implementation is separately authorized. No Google/AWS/Azure account, managed OCR request or external OCR disclosure. ADR-0008's managed comparisons remain research alternatives, not providers to call. A local result cannot validate their accuracy/privacy claims.

Use ADR-0008's 24 synthetic documents (six clean scans, six declared challenging scans, six mixed, six native controls), with independent family partitions and adjudicated labels under AA003. Map OCR text, page geometry, word boxes, source method, raw confidence and errors into AA002 evidence semantics. Mixed documents route only deficient pages; do not attach native offsets to replacement OCR text or double-count duplicated text. Native baseline retained for every applicable document.

Record CER, coverage, critical-field precision/recall, reading order, failure/abstention rate, peak memory, CPU time, wall latency including p50/p95, cleanup/cancellation and version hashes. Apply unchanged segment thresholds in CONSTRAINTS.md; a small pilot pass authorizes only further evaluation, not AA015/AA1/release validity. Worker-host measurements must precede choosing a production completion SLO.

Proposed safety limits: stricter of existing worker limits and ADR-0008 (10 OCR pages, 300 DPI, 10 megapixels/page, 100 megapixels/document; 30-second OCR deadline, 10-second attempt, concurrency two, maximum one transient retry within remaining budget). Existing total job deadline always wins. No retry for malformed/unsupported files, deterministic engine failures, cancellation or deadline exhaustion. Kill subprocess groups and clean scratch; merely abandoning a promise is insufficient.

External spend ceiling is $0. No new paid infrastructure. Before implementation, record the local machine's available CPU/memory/disk, set measured compatible hard caps, and record host cost assumptions; unknown compute cost is explicitly unknown, not “free.” This host feasibility check is an AA012 prerequisite, not permission to exceed these limits. No runtime package download, network access, shell interpolation of candidate filenames or untrusted document includes. Synthetic-only local processing does not pretend external-provider consent was granted.

Exit: archive a reproducible report and select continue-local-evaluation, revise/review or stop. Any external provider, real-data trial, expanded bounds, worker deployment or production enablement returns to human review. AA004 approves this design only; AA012 executes the adapter/evaluation after AA0 and its own prerequisites, AA013 calibrates, AA015 validates release. Those tasks remain separate.

## AA005 — first segment and unsupported behavior

Owner selection recorded 2026-10-04: **software engineering, English, India-focused resumes**, candidate B2C. The owner selected this segment in response to the AA005 question. General new-graduate roles and other domains/locales are outside the initial segment. Selection fixes the corpus taxonomy and subsequent calibration scope, not immediate released support or approval of the rest of this package.

Input plan: PDF resumes, with native single-column first; supported multi-column only after its representative gate, clean scanned/mixed only after OCR gates. Challenging scans are a separate declared segment, not silently generalized. No password-protected/corrupt PDFs, handwriting, unsupported scripts, or ambiguous layout promoted to supported. PDF and DOCX are initial _export_ targets after renderer/parity gates; DOCX input is not currently authorized by this PDF-first scope. LaTeX export/compile deferred behind ADR-0007 isolation review.

UI behavior: unsupported domain/locale/input or missing critical evidence returns explicit unsupported/review-required state, cited reason and correction/re-upload route, never a merit score of zero or success shell. Offer inspectable recovered evidence without generalized score claims. Parse View and score explanations must follow the [design system](../design/README.md) and [blueprint](../design/PRODUCT_DESIGN_BLUEPRINT.md), keyboard/reflow/accessibility requirements, visible warnings and non-color-only uncertainty. No broad UI implementation is authorized by this design package.

## Alternatives and consequences

Rejected: mark tasks complete because documents or native tests exist; select a cloud provider despite local-only scope; keep an aggregate score to simplify UX; let unknown rules receive points; silently migrate legacy scores; collect real resumes to accelerate calibration. These trade speed for misleading validity, disclosure or irreproducible semantics.

Chosen proposal: one review record, separate score dimensions, explicit unknown states, versioned immutable provenance, synthetic-first controlled evaluation and narrow first segment. Costs: more candidate review, withheld scores until calibration, independent annotator effort and slower release. Benefits: reproducible claims, reversible changes and no unnecessary vendor/data commitments.
